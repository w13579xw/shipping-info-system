# 知识图谱问答系统（论文第 2 章）

> 本章对应论文《融合知识图谱的航运信息服务系统设计与实现》第 2 章「知识图谱问答系统设计与实现」，介绍港口知识图谱的构建流程，以及基于知识图谱 + 大模型的自然语言问答系统。

---

## 1. 模块概述

航运问答模块的目标是：让用户用**自然语言**提问航运领域问题（如「上海有哪些港口」「中国的港口有哪些」），系统先尝试从 **Neo4j 港口知识图谱**中检索结构化的实体/关系答案；当问题不涉及图谱或图谱不可用时，自动回退到 **DeepSeek 大模型**直接生成回答。

## 2. 知识图谱的构建

### 2.1 数据获取

港口数据通过爬虫脚本 [`模块/港口信息爬取及构建知识图谱/spyder.py`](../模块/港口信息爬取及构建知识图谱/spyder.py) 获取，爬取结果整理为 JSON 文件 [`port_data.json`](../模块/港口信息爬取及构建知识图谱/port_data.json)（约 1.1MB）。

每条港口记录包含以下字段：

| 字段 | 含义 | 对应实体/关系 |
| --- | --- | --- |
| `港口中文` | 港口名称 | 港口 实体 |
| `城市中文` | 所在城市 | 城市 实体 |
| `国家中文` | 所属国家 | 国家 实体 |
| `地区` | 所在地区 | 地区 实体 |
| `航线中文` | 所属航线 | 航线 实体 |

### 2.2 知识图谱模式（Schema）

构建脚本 [`build_kg_utils.py`](../模块/港口信息爬取及构建知识图谱/build_kg_utils.py) 定义了 5 类实体和 4 类关系：

**实体（每个实体只有 `name` 一个属性）：**

- `港口`（Port）
- `城市`（City）
- `国家`（Country）
- `地区`（Region）
- `航线`（Route）

**关系：**

| 关系 | 方向 | 语义 |
| --- | --- | --- |
| `belongs_to` | 城市 → 国家 | 城市属于国家 |
| `located_in` | 港口 → 城市 | 港口位于城市 |
| `in_region` | 港口 → 地区 | 港口位于地区 |
| `on_route` | 港口 → 航线 | 港口在航线上 |

### 2.3 数据导入

`build_kg_utils.py` 中 `PortKnowledgeGraphBuilder` 类的构建流程：

1. `extract_triples(path)`：读取 `port_data.json`，抽取实体与三元组（主语, 关系, 宾语），过滤含空值的记录。
2. `create_entities()`：用 Cypher 的 `MERGE` 语句逐类写入实体节点（自动去重）。
3. `create_relations()`：用 `MATCH ... MERGE (p)-[r]->(q)` 写入关系边。

运行方式：

```bash
python build_kg_utils.py
```

> 脚本通过环境变量 `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` 连接 Neo4j（默认 `bolt://127.0.0.1:7687`），请先设置为你自己的 Neo4j 凭据。

## 3. 问答系统设计与实现

论文中问答系统采用经典的**「检索式知识图谱问答」流水线**（2.2 节），分为以下步骤：

```
用户问题 → 命名实体识别 → 意图识别 + 槽位填充 → 实体规范化 → 查询模板构建 → Cypher 查询 → AI 大模型语义补全 → 自然语言回答
```

在实际的 Django 集成实现中，前几步（NER、意图识别、实体规范化、查询模板构建）被**大模型驱动的「问题 → Cypher」生成**所替代，即由 DeepSeek 直接判断问题是否涉及图谱并生成 Cypher 语句，其余流程保持一致。

### 3.1 集成实现（`app01/views/qa.py`）

主接口 `ask_question`（对应路由 `POST /qa/ask`）的实现逻辑：

1. **初始化大模型客户端**：通过 `OpenAI(api_key=OPENAI_API_KEY, base_url=OPENAI_BASE_URL)` 连接 DeepSeek（OpenAI 兼容接口）。
2. **问题分析 + Cypher 生成**：向大模型传入图谱 Schema（实体/关系定义）与示例，要求其：
   - 若问题涉及图谱实体/关系，返回以 `MATCH` 开头的 Cypher 查询语句；
   - 否则返回 `NO`。
3. **知识图谱查询**：若返回 Cypher，用 `py2neo` 执行查询并对结果去重。
4. **大模型语义补全**：将查询结果交给大模型，生成自然、专业的回答。
5. **降级策略**：
   - 若问题不涉及图谱（返回 `NO`）→ 直接用大模型回答；
   - 若图谱查询出错 / Neo4j 不可用 → 回退为大模型直接回答；
   - 若大模型也不可用 → 返回友好错误提示。

### 3.2 演示问题示例

[`demo_questions.txt`](../模块/港口信息爬取及构建知识图谱/demo_questions.txt) 中给出了一个典型问题及其 Cypher：

**问题：** 位于中国且属于东南亚航线的港口有哪些？

**Cypher：**

```cypher
MATCH (port:港口)-[:located_in]->(city:城市)-[:belongs_to]->(country:国家 {name:'中国'}),
      (port)-[:on_route]->(route:航线 {name:'东南亚'})
RETURN DISTINCT port
```

## 5. 运行前提

| 服务 | 作用 | 是否必须 |
| --- | --- | --- |
| DeepSeek API Key | 问题分析、Cypher 生成、语义补全 | 是 |
| Neo4j | 知识图谱存储与查询 | 可选（缺失时回退大模型） |

**Neo4j 不可用时的降级示例**：用户提问后，系统跳过图谱查询，直接返回大模型回答，不影响其他功能。

---

## 6. 可改进点

- Cypher 语句由大模型生成，存在注入/越权查询风险，建议增加白名单校验。
- 当前每次提问都重新初始化 `PortKnowledgeGraphBuilder`，建议改为连接复用。
- 问答不支持多轮上下文，可将历史对话加入 `messages` 实现多轮对话。
