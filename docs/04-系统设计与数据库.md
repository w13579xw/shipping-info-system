## 1. 系统总体架构

### 1.1 系统分层架构

系统采用经典的 **Django MTV（Model-Template-View）** 分层架构，前端通过 HTTP 接口与后端交互：

```
┌─────────────────────────────────────────────┐
│  前端（Bootstrap + ECharts + jQuery）        │
│  页面模板 templates/ + 静态资源 static/       │
├─────────────────────────────────────────────┤
│  视图层  app01/views/                        │
│  account / user / admin / news / qa / ship / │
│  chart / forum / index / register            │
├─────────────────────────────────────────────┤
│  中间件层  app01/middleware/auth.py           │
│  登录认证 + 管理员权限控制                     │
├─────────────────────────────────────────────┤
│  工具层  app01/utils/                        │
│  bm25 / 知识图谱 / 验证码 / 加密 / 分页        │
├─────────────────────────────────────────────┤
│  数据层                                       │
│  MySQL（关系数据）│ MongoDB（新闻）│ Neo4j（图谱）│
└─────────────────────────────────────────────┘
```

![系统功能架构](../system/md_pic/system-architecture.jpg)

### 1.2 功能模块划分

| 模块 | 主要功能 | 对应视图 |

## 2. 数据库设计

系统使用三种数据库协同工作，各司其职：

| 数据库 | 存储内容 | 用途 |
| --- | --- | --- |
| **MySQL** | 用户、管理员、论坛、访问记录、浏览历史 | 关系型数据，事务一致 |
| **MongoDB** | 新闻资讯（海量文本） | 文档型数据，灵活存储 |
| **Neo4j** | 港口知识图谱（实体 + 关系） | 图数据，关系查询 |

![数据库 ER 图](../system/md_pic/er-diagram.png)

### 2.1 MySQL 数据库

关系型数据模型定义在 [`system/app01/models.py`](../system/app01/models.py)，映射到 MySQL 库 `django`：

| 表名 | 模型 | 主要字段 | 说明 |
| --- | --- | --- | --- |
| `app01_admin` | `Admin` | `username`, `password` | 管理员 |
| `app01_userinfo` | `UserInfo` | `username`, `password` | 用户 |
| `app01_post` | `Post` | `title`, `content`, `author`, `created_at`, `updated_at` | 论坛帖子 |
| `app01_comment` | `Comment` | `post`, `content`, `author`, `created_at` | 帖子评论 |
| `app01_modulevisit` | `ModuleVisit` | `module_name`, `user`, `visit_time` | 模块访问记录 |
| `app01_newshistory` | `NewsHistory` | `user`, `news_id`, `title`, `view_time` | 新闻浏览历史 |

**关系说明：**

- `Post.author` → `UserInfo`（外键，发帖作者）
- `Comment.post` → `Post`（外键，关联帖子）；`Comment.author` → `UserInfo`
- `ModuleVisit.user` → `UserInfo`（可空，游客访问）
- `NewsHistory.user` → `UserInfo`（浏览用户）

> 数据库连接配置见 [`myProject/settings.py`](../system/myProject/settings.py)，默认引擎为 MySQL，驱动使用 pymysql；密码等敏感信息通过 `.env` 注入。

### 2.2 MongoDB 数据库

新闻资讯存储在 MongoDB（库 `news_db`，集合 `news_collection`），单条文档字段：

```json
{
  "title": "新闻标题",
  "summary": "摘要",
  "body": "正文内容",
  "keywords": "关键词1 关键词2 关键词3",
  "date": "2025-01-01"
}
```

> 连接配置：`MONGODB_URI` / `MONGODB_NAME` / `MONGODB_COLLECTION`（见 `.env`）。

### 2.3 Neo4j 数据库

港口知识图谱存储在 Neo4j，实体与关系见 [01 · 知识图谱问答系统](01-知识图谱问答系统.md#22-知识图谱模式schema)。

```
实体：港口、城市、国家、地区、航线（仅 name 属性）
关系：belongs_to、located_in、in_region、on_route
```

> 连接配置：`NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD`（见 `.env`）。

## 3. 权限控制

系统通过自定义中间件 [`app01/middleware/auth.py`](../system/app01/middleware/auth.py) 实现统一的登录认证与权限控制：

- **白名单路径**：登录/注册/验证码/首页/船舶识别/问答/新闻列表/论坛等公共页面无需登录。
- **管理员路径**（`/admin/`、`/user/`、`/chart/`）：需 `admin_info` Session。
- **其他需认证路径**：需 `user_info` 或 `admin_info` Session，否则重定向登录。
- 未登录访问受限页时，中间件会保存原 URL，登录后自动跳回。
